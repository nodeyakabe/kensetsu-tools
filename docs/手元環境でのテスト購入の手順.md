## 仕組みの要点

1. 入口ページのボタンが `POST /api/create-checkout-anzen-test` を呼ぶ。
   - `STRIPE_SECRET_KEY_TEST` を使い、`STRIPE_PRICE_ID_ANZEN_TEST` でチェックアウトを作る。
   - 決済が終わると `/test/anzen/thanks/?session_id=...` に戻る。
   - `STRIPE_SECRET_KEY_TEST` が未設定なら 503 を返す。本番キーへ切り替わることはない。
2. Stripe テストモードの `checkout.session.completed` を Webhook が受け取る。
   - `STRIPE_WEBHOOK_SECRET_ANZEN_TEST` で署名を確かめる。`livemode=true` のイベントは無視する。
   - `STRIPE_PRICE_ID_ANZEN_TEST` の商品なら、ライセンスキーを作る。キーを作る秘密鍵は本番と同じ `ADAN_LICENSE_SECRET` だった。
   - キーを PaymentIntent の metadata（`adan_license_key`）に記録する（同じイベントが再送されても二重に発行しないため）。
   - Brevo（`BREVO_*`）で、キーとダウンロードリンクをメールで送る。
3. ダウンロード関数の流れ:
   - `STRIPE_SECRET_KEY_TEST` で session を照会する。
   - 支払済み・商品一致・`livemode=false`・購入から30日以内を確かめる。
   - R2（`PRODUCT_BUCKET`）から、本番と同じ `DOWNLOAD_OBJECT_KEY_ANZEN` の zip を返す。

## 手元で再現するとき

- 本番には置かない。`wrangler pages dev` などの手元環境で、上のファイルを git 履歴から戻して動かす。
- 環境変数は `.dev.vars` に置く（リポジトリには入れない）。
- **テスト専用のキー用秘密鍵**と**テスト専用のダミー zip**を使う。本番の秘密鍵と本番の zip は使わない。
- Stripe の Webhook は `stripe listen --forward-to localhost:<port>/api/stripe-webhook-anzen-test` で手元に転送する。
- テストカード: `4242 4242 4242 4242` / 有効期限は未来の任意の日付 / CVC は任意の3桁
