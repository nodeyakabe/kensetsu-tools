# 手元環境でのテスト購入の手順

## 概要

`/test/anzen/` を使って、安全台帳（単品・セット）の購入フロー全体を手元で通しテストする手順です。
本番環境・本番 R2・本番 Stripe には一切触れません。

テスト構成:
- Stripe テストモード（`sk_test_...`）
- ECDSA テスト用鍵ペア（`LicenseServiceTests.cs` の TestPrivateKey / TestPublicKey）
- ローカル R2（wrangler ステートディレクトリ）＋ ダミー zip
- Debug ビルドの安全台帳アプリ（テスト公開鍵を使う）

---

## 手順

### 0. 前提確認

| 確認項目 | コマンド例 |
|---|---|
| Node.js / npm | `node -v` |
| wrangler | `npx wrangler --version` |
| Stripe CLI | `stripe --version` |

### 1. `.dev.vars` を作成する

```bash
cd apps/HP
cp .dev.vars.example .dev.vars
```

`.dev.vars` を開き、以下の値を自分で記入する（`.dev.vars.example` にテスト用鍵は記載済み）:

| 変数 | 取得元 |
|---|---|
| `STRIPE_SECRET_KEY_TEST` | Stripe ダッシュボード → テストモード → API キー |
| `STRIPE_WEBHOOK_SECRET_ANZEN_TEST` | 手順 4 の `stripe listen` 出力を見てから記入 |
| `STRIPE_PRICE_ID_ANZEN_TEST` | Stripe テスト商品の Price ID |
| `STRIPE_PRICE_ID_SET_TEST` | Stripe テスト商品（セット）の Price ID |
| `BREVO_API_KEY` | Brevo → API Keys（省略時はコンソール出力） |
| `BREVO_SENDER_EMAIL` | Brevo 承認済み送信者アドレス |
| `BREVO_SENDER_NAME` | 表示名（例: 建設業ツール工房） |

`ADAN_ECDSA_PRIVATE_KEY_B64` / `SITE_ORIGIN` は `.dev.vars.example` に記入済みなので変更不要。

### 2. ローカル R2 にダミー zip をシードする

```bash
cd apps/HP

npx wrangler r2 object put product-bucket-local/anzen-daicho.zip \
  --file test-dummy/anzen-daicho.zip --local

npx wrangler r2 object put product-bucket-local/set-koji-anzen-v1.zip \
  --file test-dummy/set-koji-anzen-v1.zip --local
```

### 3. Astro をビルドして wrangler pages dev を起動する

```bash
cd apps/HP
npm run build
npx wrangler pages dev dist --port 8788
```

### 4. Stripe CLI でローカルに Webhook を転送する（別ターミナル）

```bash
stripe login   # 初回のみ
stripe listen --forward-to http://localhost:8788/api/stripe-webhook-anzen-test
```

起動すると `whsec_...` が表示される。
`.dev.vars` の `STRIPE_WEBHOOK_SECRET_ANZEN_TEST` にその値をコピーして保存する。

> wrangler pages dev は `.dev.vars` を起動時に読み込むため、
> 値を変えたら Ctrl+C で止めてからステップ 3 のコマンドをもう一度実行する。

### 5. テスト購入を実行する

ブラウザで `http://localhost:8788/test/anzen/` を開き、次の2パターンを試す:

**① 安全台帳 単品テスト購入**
- ボタン「① 安全台帳 単品テスト購入」をクリック
- テストカード `4242 4242 4242 4242` / 有効期限: 未来の任意の日付 / CVC: 任意3桁
- 決済後 `/test/anzen/thanks/?session_id=...` に遷移することを確認

**② 工事台帳＋安全台帳 セットテスト購入**
- ボタン「② 工事台帳＋安全台帳 セットテスト購入」をクリック
- 同じテストカードで決済
- 決済後 `/test/anzen/thanks/?session_id=...&set=1` に遷移することを確認

### 6. 動作確認チェックリスト

| # | 確認項目 |
|---|---|
| 1 | サンクスページ（`/test/anzen/thanks/`）が表示されている |
| 2 | ダウンロードボタンで zip が落とせる |
| 3 | メールにライセンスキー（`ADAN-...` 121文字）が届いている |
| 4 | メール本文の exe 名が「シンプル安全台帳.exe」になっている |
| 5 | メール本文に再ダウンロードリンクがある |
| 6 | Debug ビルドアプリでキーが認証できる |
| 7 | `/redownload/` に同じキーを入力して zip が取れる |
| 8 | Stripe テストダッシュボードの metadata に `adan_license_key` と `adan_license_nonce` が記録されている |
| 9 | Webhook を `stripe trigger` で再送しても同じキーが返る（二重発行なし） |

> **ステップ 9 の冪等性テスト**:
> `stripe trigger checkout.session.completed` ではなく、stripe listen の画面に表示された
> イベント ID で `stripe events resend <evt_...>` を実行する。

## 本番リリース後に不要になるもの

本番での通しテストが完了し、Cloudflare 本番環境でテスト用設定を削除したら:

- Cloudflare Pages 環境変数: `STRIPE_SECRET_KEY_TEST`、`STRIPE_WEBHOOK_SECRET_ANZEN_TEST`、`STRIPE_PRICE_ID_ANZEN_TEST`、`STRIPE_PRICE_ID_SET_TEST`
- Stripe テストモードの Webhook 登録（`/api/stripe-webhook-anzen-test` 宛て）

テストページ（`/test/anzen/`）自体はコードに残しておいても問題なし（noindex/nofollow）。
